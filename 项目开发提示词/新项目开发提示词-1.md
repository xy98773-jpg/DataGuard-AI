# 三、核心设计原则

## 1. Agent 负责决策，不负责计算

错误方式：

LLM直接分析百万行数据。

正确方式：

Python工具负责：

-   数据统计
-   类型检测
-   分布分析
-   格式检测

Agent负责：

-   理解结果
-   判断问题
-   制定方案

------------------------------------------------------------------------

## 2. Agent 不直接修改数据

所有修改必须经过：

Agent Plan

↓

Plan Validator

↓

Risk Engine

↓

Execution Engine

禁止：

LLM直接生成SQL并执行。

------------------------------------------------------------------------

## 3. 所有 Agent 行为必须可追踪

系统必须记录：

-   Agent输入
-   Agent输出
-   Tool调用
-   状态变化
-   延迟
-   Token消耗
-   错误信息

通过 Trace 系统展示完整执行过程。

# 七、开发要求

## 必须采用 LangGraph

禁止：

简单：

\`\`\`python agent1() agent2() agent3() 流水调用。

必须体现：

Graph State

Node

Edge

Conditional Routing

Interrupt

八、Agent数量

不要设计大量 Agent。

固定：

4个核心Agent。

1.  Supervisor Agent

职责：

任务理解

流程规划

节点路由

禁止：

调用数据修改工具。

输出： json格式: { "next_node":"profiler", "route":"file_cleaning" } 2.
Profiler Agent

职责：

理解数据分析结果。

注意：

数据统计由 Python 完成。

Profiler Agent 输入：

schema statistics anomalies

输出：

Semantic Dataset Profile。

3.  Quality Inspector Agent

职责：

发现数据质量问题。

输入：

Evidence

输出：

IssueReport。

格式： json格式: { "issues":\[

{ "id":"ISSUE001",

"type":"format_error",

"column":"phone",

"severity":"MEDIUM",

"confidence":0.96,

"affected_rows":1250,

"evidence":\[...\]

}

\] } 4. Cleaning Planner Agent

职责：

根据问题生成治理方案。

禁止：

直接执行。

输出：

CleaningPlan。

格式： json格式: { "actions":\[

{ "tool":"phone_normalizer",

"target":"phone",

"risk":"LOW"

}

\]
